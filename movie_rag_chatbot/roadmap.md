## 현재 문제점 및 개선 방향

### 1. 스포일러 판단 방식이 버전마다 다르고, 모두 아쉬움
- **바닐라 RAG**: 키워드(결말/스포/줄거리) 유무로 판단 -> "스포 없이"처럼 부정 표현을 잘못 판단할 수 있음
- **LangChain**: 검색 필터 없이 프롬프트 규칙으로 LLM이 자제 -> 100% 보장되지 않음
- **LangGraph**: 분류 노드에서 LLM(제미나이)이 판단 -> 정확하지만 질문 1건당 API를 2번씩 호출해서서 무료 한도 소진이 빠름

### 2. 개선 목표
- 스포일러 유무를 판단하는 분류 모델을 직접 구현해서 API 호출 없이 판단 -> 정확도 확보 및 API 요청 수 절감
- FastAPI + 프론트엔드를 연결해서 웹에서 실행 가능한 형태로 만들기
