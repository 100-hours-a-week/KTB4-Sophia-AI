# 🐛 트러블슈팅

## 1. [데이터] 위키백과 줄거리 수집량 부족
- **문제**: `wikipedia` 라이브러리로 줄거리를 수집했더니 줄거리 양이 너무 적었다(169/500). 그 결과, "우주를 배경으로 한 SF 영화"를 검색해도 SF 장르 영화가 추천되지 않았다.
- **원인**: 대부분의 영화가 짧은 소개(overview)만 있었는데, overview는 홍보성 문구 위주라 "SF"같은 장르나 내용 키워드가 거의 없어서 의미 검색이 잘 되지 않았다. 또, `wikipedia` 라이브러리 자체가 오래돼서 응답이 불안정했다.
- **해결**: 라이브러리 대신 위키백과 공식 API를 직접 호출하는 방식으로 변경했다. `extracts`로 본문을 받아서 `== Plot ==` 부분만 잘라냈다.

## 2. [데이터] 위키백과 공식 API로 바꿨는데도 줄거리가 27개만 수집됨
- **문제**: 수정 후에 오히려 수집된 줄거리가 27개로 줄었다.
- **원인**: 응답 상태코드가 429(Too Many Requests)로, 요청을 너무 빠르게 많이 보내서 위키백과가 차단했다.
- **해결**: 429가 오면 `time.sleep(5)` 이후 최대 3번까지 재시도하고, 요청 간격도 0.5초로 늘렸다.
- **결과**: 248/500 줄거리 수집 성공. 유실 방지를 위해 `movies.jsonl`에 저장했다.

## 3. [검색] 특정 영화(예: 인셉션)를 검색하지 못함
- **문제**: "우주를 배경으로 한 SF 영화 추천"은 답을 잘 하지만, "인셉션 줄거리 알려줘"에는 데이터에 인셉션이 있음에도 불구하고 "정보가 없다"고 답했다.
- **원인**: 질문 문장 전체("인셉션 줄거리 결말까지")로 의미 검색을 해서 "줄거리, 결말" 같은 일반 단어에 밀려서 "인셉션"이라는 제목이 상위에 잡히지 않았다. 제목 기반 검색을 만들지 않아서 발생한 문제였다.
- **해결**: 제목 기반 검색을 추가했다. 질문에 등록된 영화 제목이 포함되면 그 제목으로 메타데이터 필터링(`where`)해서 해당 작품조각을 우선 검색한다.

## 6. [LangGraph] 제미나이 응답에서 텍스트 추출 오류
- **문제**: 분류 노드에서 `'list' object has no attribute 'lower'`에러 발생
- **원인**: 제미나이가 응답(`result.content`)을 문자열이  아니라 `[{'type': 'text', 'text': ...}]` 형태의 리스트로 반환하는 경우가 있었다.
- **해결**: 응답이 리스트일 때 각 조각에서 `text`만 추출해 합치도록 처리했다. 분류 노드(spoiler 판단)와 답변 생성 노드 양쪽에 동일하게 적용했다.

---

## 7. [LangGraph] 답변이 날것(raw) 형태로 출력됨
- **문제**: 답변 내용은 정상인데, `[{'type': 'text', 'text': '실제 답변', 'extras': {...}}]`처럼 리스트/딕셔너리 구조가 그대로 출력되었다.
- **원인**: 텍스트 추출 처리를 해놓고, 정작 반환할 때 정리된 변수가 아니라 원본 `result.content`를 반환하고 있었다.
- **해결**: 반환값을 정리된 텍스트 변수로 수정했다.

---

## 8. [LangGraph / 환경] 제미나이 무료 API 사용량 초과 (429)
- **문제**: 테스트 중 `429 RESOURCE_EXHAUSTED` 에러 발생
- **원인**: 제미나이 무료 티어의 요청 한도를 초과했다. 특히 챗봇이 질문 1건당 요청을 2번 (스포일러 판단 + 답변 생성) 보내서 한도 소진이 빨랐다.
- **해결** 무료 한도가 더 넉넉한 모델로 잠시 교체해서 이용하고, 한도 초과 시 잠시 대기 후 재시도했다. 향후 분류 노드를 키워드 방식으로 바꿔 요청 수를 줄이는 방법도 있다.

- **해결**: `CORSMiddleware`를 추가해서 cross-origin 요청을 허용했다.

## 10. [데이터] 특정 영화 줄거리가 누락됨
- **문제**: 위키백과에는 줄거리가 있는데도 일부 영화의 plot이 비어 있었다.
- **원인**: 영어 제목만으로 검색하면 동명의 다른 문서로 연결됐다. 예) Titanic은 영화가 아니라 실제 침몰선 문서로 연결되었다.
- **해결**: 검색어에 `{제목} ({연도} film)`, `{제목} {film}`, `{제목}` 후보를 순서대로 시도해 영화 문서로 정확히 연결되게 했다. 빈 항목만 재검색해 기존 데이터를 보존했다.
- **결과**: 줄거리 270 -> 498/500으로 증가했다.

## 11. [검색] 감독 이름으로 검색이 안 됨
- **문제**: "크리스토퍼 놀란 영화 추천해줘"에 답하지 못했다.
- **원인**: 데이터에 감독 정보가 아예 없었고, 감독명은 영어지만 검색은 한국어로 한다는 문제가 있었다.
- **해결**: TMDB crew에서 `job == "Director"`를 추출해 데이터에 추가하고, 감독/제목/장르를 담은 "info" 청크를 임베딩 텍스트에 포함시켰다. Gemini가 한글 질문과 영어 감독명의 의미 공간에서 연결하도록 했다.

---

## 12. [스트리밍] 답변에 분류 노드 출력이 섞여 나옴
- **문제**: 스트리밍 시 답변 앞에 분류 노드의 "no" 같은 출력이 딸려 나왔다.
- **원인**: `stream_mode="messages"`는 LLM을 호출하는 모든 노드(분류 + 생성)의 토큰을 흘려보낸다.
- **해결**: 스트림의 metadata에서 `langgraph_node`값을 확인해 generate 노드의 토큰만 통과시켰다. content가 리스트로 오는 경우에는 `text`만 추출했다.

---

## 13. [배포] 동시 접속 시 응답 실패
- **문제**: 여러 명이 동시에 테스트하니 답변이 안 나와서 처음에는 동기 처리로 요청이 밀리는 문제라고 생각했다.
- **원인**: 로그를 확인하니 Gemini 무료 API 한도 초과(429)였다. 질문 1건당 Gemini를 2번씩 호출해서 발생한 문제였다. 프론트에서는 이 실패가 "서버 연결 실패"로 표시돼 서버 문제로 오해하기 쉬웠다.
- **해결**: 답변 생성 모델을 Gemini에서 Claude(Sonnet5)로 분리했다. 한도 문제가 크게 완화되고 답변 생성 속도도 빨라졌다.

## 14. [모델] Claude 전환 후 답변이 계속 실패함
- **문제**: Claude로 바꾼 뒤에도 답변을 못하고 프론트에 요청이 많다는 메시지가 자꾸 떴다. API 한도 문제가 다시 발생했나 싶어 로그를 확인했다.
- **원인**: 로그에 `anthropic.APIStatusError: overloaded_error (Overloaded)`가 찍혀 있었다. Anthropic 서버 자체가 일시적으로 과부하 상태여서 요청을 못받아준 것이었다.
- **해결**: `ChatAnthropic`에 `max_retries`를 추가해서 오류 시 자동 재시작하게 하고, 반나절 정도 기다렸다가 다시 질문을 하니 정상적으로 답변이 나왔다.

## 15. [임베딩] Gemini 무료 임베딩 하루 1000개 한도로 인덱싱 불가
- **문제**: `build_index.py`로 청크 6262개를 Gemini(gemini-embedding-001)로 임베딩하려는데 계속 429로 막혔다. 하루가 지나도 매번 일정 개수에서 멈췄다.
- **원인**: 무료 티어 임베딩 한도가 하루 1000개(RequestsPerDay)였다. 청크 6262개를 하루에 다 만들 수가 없어서 속도에 상관 없이 총량 제한에 걸렸다.
- **해결**: 임베딩을 Voyage AI(voyage-4-lite)로 전환해 6262개를 정상 생성했다.

## 16. [배포] 서버 메모리 부족으로 두번째 질문부터는 다운됨
- **문제**: 페이지는 뜨는데 두 번째 질문부터 "서버 연결 못했어요"가 떴다. 컨테이너가 죽었다가 재시작되기를 반복했다.
- **원인**: t3.micro(RAM 909MB)에 torch + 파인튜닝 모델 + 임베딩 등이 올라가 여유 메모리가 55MB 뿐이었다. 질문 처리 시 추가 메모리를 쓰다가 OOM으로 컨테이너가 죽었다.
- **해결**: 스왑 메모리를 2GB 추가하고 (`fallocate` / `mkswap` / `swapon`) fstab에 등록해서 재부팅에도 유지되게 했다. 메모리가 확보되어 안정화됐다.

## 17. [검색] 특정 영화 제목으로 물으면 줄거리(plot)를 못 찾음
- **문제**: "싸이코 스포"라고 물어보면 "줄거리 정보가 없다"고 대답했다. 데이터에는 싸이코 plot(4228자)이 존재했다.
- **원인**: 제목 위주 질문은 제목, 감독이 담긴 info 청크와만 매칭되고, 정작 줄거리 내용인 plot 청크는 벡터 유사도에서 밀려 상위 결과에 들지 못했다.
- **해결**: 제목 인식 검색(`detect_title`)을 추가했다. 질문에 등록된 영화 제목이 있으면 `filter={"title_kor": 제목}`으로 그 영화 청크만 검색해 plot을 확실히 포함시켰다.

## 18. [검색] chromadb 다중 조건 필터 오류
- **문제**: 특정 영화를 스포일러 없이 물으면 (no_spoiler 노드) `ValueError: Expected where to have exactly one operator`가 발생했다.
- **원인**: chromadb는 필터 조건이 2개 이상이면 `$and`로 묶어야 하는데 `{"title_kor": 제목, "spoiler": False}`처럼 나란히 넣어서 거부된 것이었다.
- **해결**: `filter={"$and": [{"title_kor": 제목}, {"spoiler": False}]}` 형태로 수정했다.

## 19. [모델] 스포일러 판단을 API에서 파인튜닝 모델로 전환
- **배경**: 스포일러 판단을 Gemini로 하다보니 질문당 API를 2번 호출해 한도 소진이 빨랐다.
- **해결**: KLUE-RoBERTa를 스포일러 데이터로 파인튜닝해 classify를 로컬 모델로 대체했다. API 호출이 줄고 판단이 즉시 이뤄졌다.
- **tradeoff**: 로컬 모델(torch)이 서버 메모리를 많이 써서, 스왑 메모리로 대응해야 했다.
